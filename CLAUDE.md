# Snow Shoveling Adventure

## Repos
- Frontend (this repo): `C:\ThreeJS\Snow-shoveling-adventure\Snow-shoveling-adventure`
- Backend: `C:\ThreeJS\Snow-shoveling-adventure\Snow-shoveling-adventure-backend` (Colyseus server). "Backend" always means this folder; "frontend" means this repo.

Three.js (vanilla, no React) + Vite. A snowy, walled hub (icy plaza, frosted terraced walls, shop stands, leaderboards, portal, training mounds) opening west onto a snow field with falling snowflakes, plus a DOM HUD. Everything is procedural (canvas textures, SVG icons); the only imported model is the Bloxity base rig `public/avatars/player.glb`. Font: Fredoka (Google Fonts, falls back gracefully).

- `npm run dev` / `npm run build`. `VITE_DEV_MODE=true` (see `.env.example`) skips the Bloxity SDK/CDN.
- All tunables are in `src/config.js`. All Bloxity SDK calls go through `src/bloxity.js` and must never throw (SDK may be blocked).
- `src/player.js` is the player singleton + movement (`floorAt` is the single floor lookup, backed by `colliders.js`). `src/camera.js` chase cam (own yaw/pitch, one smoothed follow point, eased wheel zoom, speed pull-back/FOV, pulls in against `segmentClear` in colliders.js). `src/world.js` canvas-painted snow ground, sky shader, lights. `src/avatar/` = rig, cosmetics loader, `rig.js` (PoseBuffer + character-space bone binding) and `animator.js` (idle/run/airborne/landing + blower-arm hold; tunables in `ANIM`), ported from +1 Cut Grass Adventure.
- `src/hub.js` walls/floor/field/frosted trees/clouds; `src/props.js` stands, NPCs, boards, portal, mounds, zone Luck signs (decorative, collidable). Solid things register boxes in `src/colliders.js` (yaw-rotated; tops within `HUB.stepUp` are walkable).
- `src/labels.js` in-world canvas text (repaints when the font loads); `src/textures.js` stud/drip/stripe/plank painters; `src/timers.js` shared countdowns.
- `src/hud.js` + `hud.css` + `icons.js`: HUD authored in 1920x991 px, each corner group scaled by `--s`. Values from `HUD_START` in config; tiles open a placeholder panel, buy buttons toast.
- Controls: WASD/arrows, Space jump, mouse look (pointer lock; right-drag where lock is refused), wheel zoom, Esc = portal menu + frees the cursor (click the world to resume), 1-3 hotbar.
- Naming: the theme is snow, but persisted/wire keys keep their old names (`state.leaves` = snow cleared, `vacuum*` = snow blowers) so saves and the backend stay compatible. Config exports `SNOW`, `SNOWFALL`; UI text says Snow/Blowers.
- Loot loop: the snow field is a diggable heightfield (`src/dig.js`, ported from Dig-sand-adventure). Each 2.5 m block (`DIG.block`) is a solid wall until dug through with the shovel; `piles.js` still tiles the field into 6 m piles per zone (hp = `SNOW.piles.baseHp * luck^exponent`, dig speed per block = `blowerPower()` x blocks-per-pile / hp x `DIG.speedScale`). A pile whose blocks are dug fires `onPileCleared`; `src/loot.js` rolls drops by zone Luck (rules in `data/loot.js`), floats them, E collects into the Bag (`state.backpackMax`, 3 now; raise it to extend). `src/sell.js` = Sell Loot stand window (E), pays value x `cashMultiplier()`. `src/interact.js` = the "E" prompt. `src/state.js` = live cash/bag/power + `subscribe`. Back in the hub the field regrows (`SNOW.piles.regrowDelay`) and loot left lying is lost. To make digging stronger, raise `state.power` / multiply into `blowerPower()`.
- Shovel: the equipped "vacuum" (`state.vacuum`, `VACUUMS` in config.js; ids/saves/backend unchanged) is a shovel. `src/avatar/heldShovel.js` (procedural model + two-hand IK), `avatar/digStroke.js` + `ANIM.dig` (stroke; `animator.js applyDig` fires `dig.impact`/`dig.thrown` -> puffs and `digSound.js`), looks per id in `data/shovels.js`, HUD tiles via `vacuumModels.js buildVacuum`. Held input is still `inputState.blow` / pose `'blow'` on the wire.
- Tutorial (new accounts only): `src/tutorial.js` (banner, 3D guide arrows, UI arrow on the Sell All / close / vacuum buttons) driven by the pure step machine `tutorialLogic.js`; tunables in `TUTORIAL` (config.js). `state.tutorialStep` is saved (`SAVED`); the backend sends `tutorialStep` = finished for docs that predate it and only ever raises it (`$max`), so existing players never see it. `state.tutorialReady` (set by net.js once the server answers) gates it. `TUTORIAL.steps` must match the backend's `TUTORIAL_DONE_STEP`.
- Multiplayer/saves: `src/net.js` talks to `../Snow-shoveling-adventure-backend` (Colyseus room `world`, `VITE_SERVER_URL_DEV` / `_MAIN` per channel (`npm run dev` defaults to `ws://localhost:2567`); empty = endpoint from `SDK.net.resolveEndpoint(GAME_SLUG)`; no SDK either = offline). It loads the saved doc into `state` (`progress`), debounce-saves the `SAVED` keys, sends pose/vacuum/aura/avatar, and feeds the hub leaderboards (`props.js`). `src/remotePlayers.js` draws the other players from `room.state.players`. The id lists/caps in the backend's `constants.ts` must match `config.js`.
